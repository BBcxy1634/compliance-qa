B2 与 B1 只改变检索方式。切分、生成 Prompt、Top 5、判题方式和评测集均保持不变。

## 原理

BGE-M3 向量检索根据语义相似度寻找内容。即使问题和原文没有完全相同的关键词，只要语义接近，也可能召回。

BM25 根据词频和稀有词匹配寻找内容。它对品牌名、型号、公告编号、专有名词和精确关键词比较敏感，但不理解同义词和跨语言语义。

两路检索各自返回最多 20 个候选。RRF 不直接比较两种分值的绝对值，而是只使用排名进行融合：

```text
RRF score(chunk) = sum(1 / (60 + rank_in_each_route))
```

一个 chunk 在向量和 BM25 两路中排名都靠前时，会获得更高融合分数。融合后截取 Top 5。

RRF 的优点是不需要把余弦相似度和 BM25 分数强行归一化，适合异构检索结果的融合。

## 结果解释

B2 的总体答案正确率与 B1 持平，均为 0.90，但内部结构发生了变化：

- 事实题从 37/40 提升到 38/40。
- 多跳题从 8/10 下降到 7/10。
- Gold unit recall 从 0.9767 略降到 0.9733。
- 可答题误拒答从 0 增加到 1。

对比逐题结果，B2 只在两道题上改变了正确性：

- q037 从错误变为正确。BM25 对 ERP、平台数量、预算、售后等关键词的精确匹配补充了向量结果。
- q044 从正确变为错误。该题需要同时使用 eBay 反馈政策和冒犯性材料政策，但 BM25 加入后，Top 5 主要被反馈政策的多个片段占据，第二个政策来源被挤出，最终模型拒答。

B2 的意义不是证明混合检索总是提升，而是证明在当前高召回基线上，RRF 对事实型精确词匹配有帮助，但可能稀释多跳题需要的跨来源覆盖。

由于 B1 的 Hit@5 已经达到 1.0，混合检索无法在“是否命中正确来源单元”上获得可见提升。B2 更适合观察复杂检索行为和后续 B3 重排是否能修复多跳上下文丢失。

延迟方面，P50 比 B1 低 145.06 ms，但 P95 比 B1 高 413.91 ms。单次运行的延迟会受网络和系统负载影响，不能据此认定混合检索降低了延迟；D11 会使用更多样本做正式 benchmark。
