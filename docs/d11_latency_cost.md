# D11 延迟与成本基准

测试日期：2026-10-31  
评测方式：每套配置预热 3 次，关闭应用问答缓存，连续 100 次请求  
判题：不纳入压测，只测检索到完整答案返回  
并发：1

## 测试方法

60 条冻结问题按顺序循环使用，直到累计 100 个样本。模型首次加载和 3 次预热请求不计入 P50/P95。

最终答案模型使用 `deepseek-chat` 别名，服务端实际返回 `deepseek-flash`。

由于 2026-10-31 是周六，100 次请求全部处于 DeepSeek 空闲时段。成本按照官方价格页在测试日的人民币单价计算，并分别记录 prompt cache hit、cache miss 和 completion token。

应用层没有问答缓存。DeepSeek 服务端仍可能对重复 system prompt 和问题前缀进行上下文缓存，因此记录并单独计价。

## 对比配置

| 名称 | 检索 | DeepSeek 思考模式 | 输出上限 | 答案正确率 |

| B1 | BGE-M3 向量 Top 5 | 默认开启，effort=high | 1200 | 0.90 |

B1 Fast 使用更精炼的生产 Prompt 和 600-token 上限。完整 60 题复测显示，其正确率没有下降，反而从 0.90 提升到 0.92。

## 成本计算

`deepseek-flash` 在空闲时段的价格：

- 输入 cache hit：¥0.02 / 百万 token
- 输入 cache miss：¥1.00 / 百万 token
- 输出：¥4.00 / 百万 token

计算方式：

```text
单次成本 =
  cache_hit_tokens × 0.02 / 1,000,000
  + cache_miss_tokens × 1.00 / 1,000,000
  + completion_tokens × 4.00 / 1,000,000
```

价格来源：

```text
https://api-docs.deepseek.com/zh-cn/quick_start/pricing
```

100 次请求中约 89% 的 prompt token 命中服务端缓存。即使不考虑缓存，当前成本仍远低于单次 ¥0.01 的目标。

高峰时段价格为空闲时段的两倍。按高峰价保守换算：

- B1 Fast P95 单次成本约 ¥0.00457。
- B3 P95 单次成本约 ¥0.00540。

两者仍低于 ¥0.01。

## 延迟分析

B1 Fast 的 P95 中：

- 检索 P95 约 213.04 ms。
- 生成 P95 约 3156.83 ms。

网络模型生成占主要耗时。关闭思考、缩短输出后，P95 从 3366.01 ms 降到 3313.10 ms，3 秒内完成率从 84% 提升到 87%，但仍高于目标约 313 ms。

B3 的 P95 中：

- 重排 P95 约 8686.49 ms。
- 生成 P95 约 3945.74 ms。

CrossEncoder 在 CPU 上处理 8 个候选是 B3 的主要瓶颈，因此 B3 不适合作为所有请求的默认在线链路。

## 结论与选择

1. 成本目标已经满足，三个配置的 P95 单次成本都低于 ¥0.01。
2. B1 Fast 是当前最推荐的默认链路：正确率 0.92，平均延迟约 1.92 秒。
3. B1 Fast 的 P95 仍为 3313.10 ms，未满足 3 秒目标；报告必须如实记录。
4. B3 质量最高，但 P95 约 12.31 秒，适合作为多跳或高质量按需模式。
5. 重排模型的主要优化方向是 GPU、量化、减少候选数或按需启用。
6. DeepSeek 的主要优化方向是控制长尾输出、流式反馈、合理缓存供应商前缀或评估其他等效模型。
